# 架构与一致性约束

## 状态所有权

`GameEngine` 是唯一规则写入者。QML 只能经由 `GameViewModel` 创建 `GameCommand`；联机客户端的命令先经过席位授权，再由房主的同一个 `GameEngine` 校验。UI 动画不得提前改变资产、位置或产权。

权威状态通过 `GameState::toCbor()` 序列化。快照带稳定 SHA-256 截断哈希；客户端校验后才替换本地状态。不兼容的协议版本和存档规则版本直接拒绝，不做静默猜测。

## 场景空间

- 地图世界坐标使用整数网格，屏幕投影统一为等距投影。
- 每个地块只拥有一个世界锚点；建筑、人物、装饰均从锚点派生。
- 地面先绘制，建筑与人物进入统一深度队列，当前人物最后绘制可见性轮廓。
- 当前人物所在地产的建筑体以 25% 不透明度绘制，防止人物被完全遮挡。
- 建筑体量必须保持在单地块安全范围；测试拒绝重复世界锚点。

## 更新信任链

更新清单的签名消息严格为：

```text
channel\nversion\nurl\nsize\nsha256-hex
```

启动器依次验证 HTTPS、字段上限、Ed25519 签名、下载长度和 SHA-256。任何一步失败都删除暂存文件且不覆盖现有安装。生产构建缺少 libsodium 或公钥时拒绝远程更新。
